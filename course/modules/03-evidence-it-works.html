Replays depend on timing. Killing the ingestors only causes a replay if the kill lands between an insert and its acknowledgement. In the attempts captured for this course ClickHouse dropped 1, 0, 0 replayed inserts (the count varies from run to run). Every attempt ended with exact counts, so the result shows that nothing was lost or duplicated, and does not show that a replay happens every time.

Latency from event to queryable

For every row, latency is the time ClickHouse recorded the insert minus the time the event happened, so it covers the whole path. The collector flushes every 100 milliseconds in this stack, which is tuned for fast results. Module 11 shows what such a setting would cost on AWS.

What these results do not show

Open limits. The platform has not run on real AWS S3, and it has not been load-tested at production volume of about 1,100 events and 7,600 metric samples per second. The tests ran on one machine, natively on arm64; the verification was repeated on emulated amd64 before the checkout flow was added, and there has been no run on real x86 hardware. A crash of the collector loses what it holds in memory. These and the other limits are listed in module 11.
