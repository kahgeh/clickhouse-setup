Configuration

Everything is a container configured by YAML and environment variables, so the same images and files move to another environment by changing the environment.

Collector

stack/config/otel-collector.yaml defines one exporter per signal, opendata/logs, opendata/traces and opendata/metrics, which differ only in their paths. Environment-specific values are read from the environment:

object_store:
  type: s3
  bucket: ${env:BUFFER_BUCKET}
  region: ${env:AWS_REGION}
  endpoint: ${env:S3_ENDPOINT:-}

Locally, compose.yml sets S3_ENDPOINT to the RustFS service. On AWS the variable is left empty, the endpoint falls back to the real S3, and credentials come from the task or pod IAM role. The other exporter settings in the file are flush_interval: 100ms, flush_size_bytes: 4194304, compression: zstd and timeout: 30s. The 100 ms flush is tuned for fast results locally, and module 11 shows its cost on AWS.

Ingestors

Each ingestor reads stack/config/ingestor-<signal>.yaml. The three files differ in signal, manifest_path and data_prefix. Selected settings:

SettingValueEffect
runtime.poll_interval_ms250How often the ingestor checks the manifest.
runtime.retry_max_attempts6Retries with backoff before an error is surfaced.
ack.policyevery_commit_groupAcknowledge a range after each committed group.
adapter.max_chunk_rows and max_chunk_bytes10000 and 4194304Upper bounds for one insert, and inputs to the token fingerprint.
adapter.apply_deduplication_tokentrueSend the idempotency token with every insert.

Any setting can be overridden by an INGESTOR__* variable, with a double underscore for each level of nesting. The files name INGESTOR__CLICKHOUSE__ENDPOINT, INGESTOR__CLICKHOUSE__USER, INGESTOR__CLICKHOUSE__PASSWORD and INGESTOR__BUFFER__OBJECT_STORE__BUCKET. INGESTOR__BUFFER__OBJECT_STORE__REGION overrides the region written in the YAML. Object-store credentials and the endpoint come from the standard AWS_* variables.

The logs table

This excerpt is taken line by line from evidence/ddl.sql, which is a copy of stack/clickhouse/10_logs.sql. The columns in the middle are omitted.

CREATE TABLE IF NOT EXISTS otel.otel_logs
(
    Timestamp          DateTime64(9) CODEC(Delta(8), ZSTD(1)),
    TraceId            String CODEC(ZSTD(1)),
    -- ... 14 more columns omitted ...
    _odb_sequence          UInt64,
    _odb_entry_index       UInt32,
    _odb_record_index      UInt32,
    _odb_manifest_path     LowCardinality(String),
    _odb_data_path         String,
    _odb_ingestion_time_ms Int64,
    _adapter_version       UInt32,
    -- Server-side insert time: end-to-end latency = _odb_clickhouse_inserted_at - event time.
    _odb_clickhouse_inserted_at DateTime64(9) DEFAULT now64(9),
    -- ... 3 skip indexes omitted ...
)
ENGINE = ReplacingMergeTree(_adapter_version)
PARTITION BY toDate(Timestamp)
ORDER BY (toStartOfFiveMinutes(Timestamp), ServiceName, Timestamp, _odb_sequence, _odb_entry_index, _odb_record_index)
TTL toDateTime(Timestamp) + INTERVAL 30 DAY
SETTINGS index_granularity = 8192, ttl_only_drop_parts = 1, non_replicated_deduplication_window = 1000;
LineWhat it does
_odb_sequence, _odb_entry_index, _odb_record_indexProvenance: which queue sequence, which entry in it and which record in that entry the row came from. Together they identify a record.
_odb_manifest_path, _odb_data_path, _odb_ingestion_time_msProvenance: the manifest and the data object the row was read from, and when the ingestor read it.
_adapter_versionThe adapter version, and the version column that ReplacingMergeTree uses to choose which of two rows to keep.
_odb_clickhouse_inserted_at DEFAULT now64(9)The server's own insert time. End-to-end latency is this value minus the event time.
ENGINE = ReplacingMergeTree(_adapter_version)Rows with the same sort key collapse on merge.
PARTITION BY toDate(Timestamp)One partition per day, so expiry drops whole days.
ORDER BY (toStartOfFiveMinutes(Timestamp), ServiceName, Timestamp, _odb_sequence, ...)The sort key. The time bucket and service come first so time-bounded searches skip data. The three provenance columns at the end make the key unique per record, which is what lets duplicates collapse. Dropping them would let distinct records with the same time and service collapse into one.
TTL toDateTime(Timestamp) + INTERVAL 30 DAYRows expire 30 days after their event time. With ttl_only_drop_parts = 1 ClickHouse removes whole parts only.
non_replicated_deduplication_window = 1000ClickHouse remembers the tokens of the last 1,000 inserts and drops a repeat. This is what makes the insert token work on a single node.

The traces table has the same provenance and settings, with the sort key (ServiceName, SpanName, toDateTime(Timestamp), _odb_sequence, _odb_entry_index, _odb_record_index). A read-only user hyperdx_ro with SELECT on the otel database is what HyperDX uses.

Setup checklist

Run the commands from the stack/ directory. Tick each step when its expected result appears. Progress is stored in your browser only. Outputs marked as examples come from a real run, and the numbers and times will differ on your machine.

0 of 9 steps done 

  1. docker build -t sre-app:dev                       ../app

docker build -f ../ingest/connectors/clickhouse-ingestor/Dockerfile -t sre-ingestor:dev ../ingest

    Expected. Each build finishes without an error and tags sre-app:dev, sre-collector:dev and sre-ingestor:dev. The first build takes a while.

Moving to AWS

The README maps the local stack to AWS by changing configuration: an S3 bucket instead of RustFS, the collector and ingestors as container deployments, ClickHouse on ClickHouse Cloud or EC2 or EKS, and secrets from a secrets service instead of the development defaults. This has been documented and not executed. Module 11 has the full mapping and the open limits.
